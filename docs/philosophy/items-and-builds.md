# Items and builds

What an item has to be for a loot game to become a build game. The ceremony
around a drop is in [loot-fountain.md](loot-fountain.md); this file is about
what is inside it.

## Principles

### The rarity ladder is a hierarchy of meaning

> A player must understand why an item matters before reading every stat line.

Names and colours are incidental. What matters is that each tier has a
distinct job, roughly:

- lowest: salvage and starter gear;
- next: early usable gear;
- middle: meaningful stat packages;
- upper: specialised build pieces;
- top: **rule-changing powers**;
- alongside: set pieces, which contribute to a named synergy;
- beyond: rare chase variants for the long term.

A tier that is only "the same, with bigger numbers" has no job.

### Rule-changing powers carry the build game

Plain stat lines (+4% attack, +7% health) can exist as background progression.
They cannot carry a build game. The memorable item alters a skill, a trigger,
a resource loop, a damage type, a projectile pattern, a cooldown or a survival
mechanic.

A good power makes the player ask:

- Which skills trigger it most often?
- Which stats scale it?
- Which other item forms a feedback loop with it?
- Is it for bosses, dense groups, survival, speed or offline farming?
- Does it justify changing the whole loadout?

If a power raises none of these, it is a stat line in disguise. Prefer powers
with a cost or a condition ("but", "when", "every third") over flat bonuses,
and powers that interact with other powers over ones that stand alone.

This is also what gives the player a reason to come back between automated
runs.

### Relevance is a mix, not a maximum

Not every drop should be an upgrade. Each drop should have a credible chance
of being relevant. Automated farming produces volume, and without weighting
the player sorts junk instead of making decisions.

The player should see a mixture of:

- immediate opportunities (fits what is equipped now);
- future opportunities (fits a neighbouring build);
- crafting progress (materials, currency);
- occasional surprises.

A starting shape to test, not a rule: about 60% relevant now, 20% adjacent,
15% general or material, 5% surprising. If everything matches the current
loadout, discovery dies. If almost nothing does, the game is inventory labour.

Activities can shift the weights toward a slot, element, family or set. That
is what makes targeted farming possible (see
[build-laboratory.md](build-laboratory.md)).

### Sets give direction, not a uniform

Thresholds make collecting legible: "one more piece and the next bonus turns
on". That anticipation is the value of a set.

The failure to avoid is the mandatory full set that makes every other item
irrelevant. Guard against it:

- keep sets small (two to four pieces);
- leave slots open for other choices;
- let a set bonus create a build direction, not multiply all damage by a huge
  generic amount;
- consider collection bonuses that do not require wearing everything, and
  mix-and-match families or tags.

> The player should make a build, not merely assemble a mandatory uniform.

### What can be done with an item

A meaningful drop offers more than equip-or-ignore: compare, lock, salvage,
keep for a future build. Keeping an item for later is itself a build decision
and a reason to return.

## For Horse Heroes

- There are three tiers (Common, Uncommon, Rare) and they differ only in stat
  points. By the test above none of them has a job yet. The first tier with a
  job is the one that carries a gear effect.
- A piece fits one named horse and one of three slots, so there are nine slots
  in the party. A set can span horses: a party-wide set of three pieces, one
  per horse, is small, leaves six slots open, and is something a single-hero
  game cannot do.
- Every drop already fits a horse the party has, so "relevant now" is nearly
  free. The mix to watch is upgrade against sidegrade against material.
- There is nowhere to keep a piece that is not equipped. Until there is, "a
  drop might change my build" cannot be true of anything the player is not
  ready to wear at once.
- All of it is data (pillar 4): tiers, powers, sets, weights.
