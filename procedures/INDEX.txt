PROCEDURES
==========
One routine per file. Read the file and follow it; do not work from memory.

setup-toolchain.txt   "set up the project", "install rust"
                      Install Rust, create the Bevy project, get a window open.
                      DONE 2026-10-09 on this machine. Only needed again for a
                      second machine or a fresh clone.

build-and-run.txt     "run the game", "build it", "does it work"
                      The working loop: check, test, run, read the output.

tune-loot-feel.txt    "the drops feel off", "tune the loot shower", "more juice"
                      Change one feel parameter at a time and look at the result.

end-session.txt       "end the session", "wrap up", "we're done for today"
                      Stop what we started, build green, code commit, update
                      the record, a new session log, docs commit, verify clean,
                      summarise.

intake-source-file.txt  "intake this", "process this file"
                      Turn a file of design notes into philosophy docs and
                      GitHub issues.

record-a-design-change.txt  "I want to change", "let's scrap that"
                      Put a design change the owner states in chat into
                      vision.md and the issues it touches.

next-thing.txt        /next, "next thing", "keep going", "build the next part"
                      Pick one thing and start: bugs first, then tests, then
                      the next feature issue of the earliest release.

answers.txt           /answers, "ask me something", "what's still open"
                      Ask the owner one open question, commit her answer,
                      update the issues it touches, file the work it makes,
                      and end the session.

release-a-build.txt   "release x.y.z", "build the installer"
                      Freeze the version, build and stage, package with Inno
                      Setup, test, publish a GitHub Release.

walk-the-click-budget.txt  "walk the click budget", "count the clicks"
                      Do the common jobs in the running game by pointer and
                      by keys, and put the counts beside their budgets.

overnight-soak.txt    "run it overnight", "soak it", "leave it running"
                      The game plays itself for hours with a record of every
                      hit, drop and departure, is closed, and the record is
                      checked: pwsh tools/soak.ps1.
